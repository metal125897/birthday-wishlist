## Публичная страница

1. Загружаются 57 подарков.
2. Карточка без описания не раскрывается; с описанием раскрывается мышью и клавиатурой.
3. Несколько карточек могут быть раскрыты одновременно.
4. Ссылки открываются в новой вкладке и не сворачивают карточку.
5. Все фильтры и четыре сортировки работают; счётчик пересчитывается.
6. При сортировке по цене подарки без цены остаются в конце.
7. После нажатия брони кнопка остаётся в состоянии «Сохраняем…» до серверного подтверждения, затем бронь появляется во втором браузере.
8. Снятие брони требует модального подтверждения; Esc, фон и крестик закрывают окно.
9. Ошибка записи не ломает список и показывает русское сообщение.
9.1. При ошибке записи карточка возвращается к последнему подтверждённому статусу; сообщение об успехе не появляется.
9.2. Перезагрузка или закрытие вкладки во время «Сохраняем…» вызывает стандартное предупреждение браузера о незавершённой записи.
10. На 390×844 нет горизонтального скролла; кнопки удобны для касания.
11. На ширине 768 px фильтры и сортировка остаются в одной строке, не растягиваются на всю панель и не пересекаются.
12. Карточки сохраняют спокойный полупрозрачный фон и читаемость в закрытом, раскрытом, hover и забронированном состояниях; hover показывает общий мягкий блик без локального света под курсором, шеврон меняет направление без текстового глифа.
13. Ссылки в описаниях имеют шампань-цвет, переносят длинные URL и открываются в новой вкладке.
14. На 390 px заголовки начинаются с одной левой линии, шевроны стоят в фиксированной правой колонке, а нижний отступ после кнопки одинаков у карточек с описанием и без него.
15. На 390 px карточка с ценой показывает цену и шкалу желания в одной строке и имеет ту же базовую высоту, что карточка без цены.
16. На 1440 px кнопка во всех закрытых карточках имеет одинаковый нижний отступ, а многострочное название центрируется по вертикали единым блоком.
17. Блок «Что лучше не дарить» находится между панелью управления и списком, в закрытом виде занимает одну строку, раскрывается мышью и клавиатурой и не создаёт горизонтальный скролл на 390 px.

## Админка

1. Без сессии видна только форма входа.
2. Неверные данные не дают доступ.
3. Первый вход в пустую базу создаёт стартовый список один раз.
4. Можно создать, отредактировать и удалить подарок.
4.1. Без перезагрузки страницы последовательно отредактировать минимум два разных подарка; после каждого сохранения кнопка снова активна.
4.2. При удалении карточка остаётся на месте с кнопкой «Удаляем…» до подтверждения Firestore и после ответа сервера не появляется снова.
4.3. Кнопки «Удалить» и «Отмена» во втором шаге имеют минимальную высоту 48 px на desktop и mobile.
5. Новый подарок всегда `available`; статус в форме не редактируется.
6. Logout возвращает форму входа.
7. «Скачать CSV» создаёт UTF-8 файл со всеми текущими подарками и ровно четырьмя столбцами: название, описание, уровень желания и цена; пустая цена остаётся пустой ячейкой.

## CI/CD

- `npm run check` проходит локально.
- При ошибке любой проверки шаги загрузки артефакта и публикации GitHub Pages не выполняются.

## Security Rules

Проверить в Emulator/Rules Playground:

- unauthenticated read — allow;
- unauthenticated update только `status` — allow;
- unauthenticated изменение `title`, create и delete — deny;
- authenticated valid create/update/delete — allow;
- документ с лишним полем, неверным типом или диапазоном — deny.

## После публикации

Открыть сайт без VPN через домашнего провайдера и мобильный интернет. Проверить публичную страницу и Firebase-запросы в DevTools. Повторить бронь в обычном и приватном окне.
