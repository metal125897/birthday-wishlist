- JSON-файлы парсятся без ошибок.
- `app.js`, `admin.js`, `categories.js`, `firebase-client.js`, `firebase-config.js`, `seed-data.js` проходят `node --check`.
- Все относительные `src`/`href` из HTML существуют.

- Обе HTML-страницы содержат усиленные `noindex`-директивы для общих роботов, Googlebot и Bingbot; публичная страница не ссылается на `/admin/`.

## Админка

1. Без сессии видна только форма входа.
2. Неверные данные не дают доступ.
3. Первый вход в пустую базу создаёт стартовый список один раз.
3.1. Первый локальный снимок с `fromCache: true` и пустым кэшем не запускает заполнение; при существующем хотя бы одном детерминированном документе транзакция заполнения отменяется без перезаписи.
4. Можно создать, отредактировать и удалить подарок.
4.1. Без перезагрузки страницы последовательно отредактировать минимум два разных подарка; после каждого сохранения кнопка снова активна.
4.2. При удалении карточка остаётся на месте с кнопкой «Удаляем…» до подтверждения Firestore и после ответа сервера не появляется снова.
4.3. Кнопки «Удалить» и «Отмена» во втором шаге имеют минимальную высоту 48 px на desktop и mobile.
5. Новый подарок всегда `available`; статус в форме не редактируется.
6. Logout возвращает форму входа.
7. «Скачать CSV» создаёт UTF-8 файл со всеми текущими подарками и ровно пятью столбцами: название, описание, уровень желания, цена и категория; пустые цена и категория остаются пустыми ячейками, категория экспортируется русской подписью.
8. Категория сохраняется при создании и редактировании, текущее значение предвыбрано, а «Без категории» записывает `null`; в строке списка мини-пометка видна только при наличии категории.
8.1. Меню категории в форме использует стеклянный listbox сайта, показывает отметку текущего выбора и управляется мышью, стрелками, Home/End и Escape без системного выпадающего списка.
8.2. На 390 px желание, цена и категория находятся в первой строке метаданных, статус и «с описанием» — во второй; наличие категории или описания не добавляет третью строку.
9. Кнопка «Что не дарить» открывает редактор с актуальными значениями. «Отменить», крестик и клик по фону закрывают его без записи; «Сохранить» ждёт подтверждения Firestore, обновляет оба поля и снова разблокируется.
10. На сенсорном экране выбор желания 1–5 не мигает синим; Tab и стрелки сохраняют видимый фокус и меняют выбранное значение.
11. У описания нет углового resize-маркера. Проверить ввод и вставку многострочного текста, удаление до короткого текста, открытие длинного/короткого описания через «Изменить», «Отменить» и смену ширины 1440↔390: весь текст помещается по высоте, пустая форма возвращается к базовым семи строкам.
12. Цена не показывает стрелочки ни в обычном состоянии, ни при фокусе/наведении. Ввод и вставка принимают пусто, `0`, `9999999`, максимум семь цифр; `-`, `+`, `.`, `,`, `e`, буквы и восьмой знак не меняют значение. Паста ` 123 ` даёт 123, дроби и отрицательные цены не превращаются в другие числа. Проверить выделение и замену части цены, Backspace/Delete, Ctrl+A/C/V; сохранение пустого поля даёт `null`, нуля — числовой 0.
13. На 1440×900, 1920×800 и 390×844 с длинным списком и длинным описанием прокрутить к кнопкам формы: «Добавить подарок»/«Сохранить изменения» доступны до конца правого списка; внутри формы нет дополнительного scrollbar. Цена 0 отображается на публичной карточке и идёт перед положительными ценами при сортировке по возрастанию.
14. На 1440×900 и 390×844 расстояния от подписей «Название подарка», «Уровень желания», «Примерная цена», «Категория» и «Описание» до соответствующих полей одинаковы: 8 px после строки текста с учётом общего line-height. Проверить также общую левую линию подписей; семантика `fieldset`/`legend` сохраняется.
15. Переключатель желания по рамке, активному фону, скруглениям, кеглю и внутренним отступам соответствует переключателю статуса на главной. На 1440 и 390 px подложка плавно перемещается 1→5, 5→2 и при быстрых повторных кликах; после остановки точно совпадает с выбранной цифрой. Проверить стрелки клавиатуры, программную смену `checked` при редактировании, сброс к 1 и reduced motion. Значение желания в форме остаётся выбранной радиокнопкой.

## CI/CD

- `npm run check` проходит локально.
- При ошибке любой проверки шаги загрузки артефакта и публикации GitHub Pages не выполняются.
- `npm run snapshot:data` создаёт непустой `data/firestore-snapshot.json`, а `npm run snapshot:validate` проверяет уникальность ID, диапазоны, статусы, категории и оба поля блока.

## Security Rules

Проверить в Emulator/Rules Playground:

- unauthenticated read — allow;
- unauthenticated update только `status` — allow;
- unauthenticated изменение `title`, create и delete — deny;
- unauthenticated изменение `category` — deny;
- authenticated valid create/update/delete — allow;
- `category: null`, отсутствие поля у старого документа и каждое из пяти допустимых значений — allow для администратора; произвольное значение — deny;
- документ с лишним полем, неверным типом или диапазоном — deny.
- Цена 0 и 9 999 999 — allow для администратора; -1, 10 000 000, дробь и строка — deny. Публичное изменение цены — deny; публичная смена только статуса у подарка с нулевой ценой — allow.
- unauthenticated read `siteContent/giftGuidance` — allow; unauthenticated create/update/delete — deny; authenticated valid create/update — allow; delete, пустая строка, лишнее поле или строка длиннее 4000 символов — deny.

## После публикации

Открыть сайт без VPN через домашнего провайдера и мобильный интернет. Проверить публичную страницу и Firebase-запросы в DevTools. Повторить бронь в обычном и приватном окне.
