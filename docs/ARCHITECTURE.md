# Архитектура

## Редактируемый контент и резервная копия

Помимо коллекции `gifts`, Firestore содержит одиночный документ `siteContent/giftGuidance`. Публичный клиент подписывается на него отдельно и безопасно выводит `things` и `brands` через `textContent`; при отсутствии документа остаётся встроенный HTML-текст. Админ-клиент создаёт или заменяет документ через `setDoc` и ждёт подтверждения Firestore перед сообщением об успехе.

`data/firestore-snapshot.json` — версионируемая резервная копия прикладных данных для истории Git. Сайт не загружает её в браузер, поэтому она не может затереть Firestore. Перед каждым коммитом снимок обновляется командой `npm run snapshot:data`.

## Обзор

```text
Браузер гостя ─┐
               ├─ Firebase JS SDK ─ Firestore collection: gifts
Браузер админа ┘          │
        │                 └─ Firestore Security Rules
        └─ Firebase Authentication (администратор и анонимный гость)

Статические файлы: GitHub Pages / GitLab Pages
```

Приложение не имеет собственного сервера и не требует платного runtime. HTML, CSS и JavaScript публикуются как статические файлы; правила Firestore выполняют серверную авторизацию и валидацию.

## Потоки данных

### Загрузка списка

`app.js` подписывается на коллекцию `gifts` через `onSnapshot`. Любое изменение Firestore отображается у открытых посетителей без перезагрузки.

Фильтры категории и статуса последовательно применяются в памяти к одному уже загруженному массиву, после чего результат сортируется. Переключение категории не выполняет дополнительных запросов к Firestore. Канонический список из пяти категорий экспортируется из `categories.js` и используется обоими клиентами; отдельной коллекции категорий и CRUD для неё нет. В Firestore сохраняются стабильные английские коды, а `categories.js` отображает их русскими подписями. Поэтому переименование интерфейса не требует миграции и не сбрасывает уже назначенные категории.

### Бронирование

Гость отправляет `update` только поля `status`. Правила сравнивают старый и новый документ через `diff().affectedKeys()` и отклоняют любые другие изменения. Пока Firestore не подтвердил запись, карточка остаётся в состоянии `aria-busy`, кнопка заблокирована и показывает «Сохраняем…». Локальный optimistic snapshot не считается успехом: клиент хранит последний подтверждённый сервером статус, дожидается `waitForPendingWrites()`, затем показывает результат. При ошибке отображается подтверждённое предыдущее значение. `beforeunload` предупреждает о попытке закрыть или перезагрузить страницу, пока есть незавершённая запись.

### Администрирование

`gift-price.js` задаёт единый диапазон цены и строгий разбор текстового поля для клиентов и проверки снимка. Пустая строка даёт `null`, только 1–7 цифр дают целое число, включая 0; любой другой текст не преобразуется в цену. Firestore повторяет диапазон на сервере.

Firebase Auth выдаёт сессию официальному SDK. После авторизации правила разрешают CRUD. Рабочая админка не заполняет пустую базу автоматически. Сохранение и удаление сериализованы: форма, список и выход заблокированы до ответа сервера. При ошибке форма разблокируется, введённый текст сохраняется. Локальные snapshots с `hasPendingWrites` не считаются завершённой записью.

CSV-экспорт формируется полностью в браузере из последнего подтверждённого снимка `state.gifts`. Файл использует UTF-8 BOM, разделитель `;`, содержит русскую подпись категории отдельным пятым столбцом и не отправляет данные сторонним сервисам. Блок нежелательных подарков хранится в siteContent/giftGuidance; HTML содержит только резервный текст.

## Пути и публикация

У страницы один вертикальный scroll owner — корневой документ. `body` обрезает внепоточные декоративные слои через `overflow: clip`, а не `hidden`, чтобы короткие результаты фильтрации не создавали вложенную вертикальную прокрутку. Корень резервирует место под scrollbar через `scrollbar-gutter: stable`.

Все пути в HTML относительные. Это обязательно для project-site вида `https://user.github.io/repository/`. Админка открывается как `./admin/`, а из неё публичная страница — `../`.

## Зависимости

Firebase SDK 12.18.0 загружается как browser ES modules с `www.gstatic.com`. Сборщик пакетов не используется. При переходе на bundler нужно сохранить относительные пути, выход `dist/` и правила из `AGENTS.md`.

Для быстрой первой отрисовки HTML заранее открывает соединения с CDN Firebase и Firestore, декоративные изображения ниже hero загружаются лениво, а карточки вне viewport на desktop используют `content-visibility: auto`. На узких экранах и сенсорных устройствах, включая запрос компьютерной версии, карточки рисуются обычным способом без фонового blur: это уменьшает пересоздание графических слоёв при смене режима. Четыре CSS-веса Inter ссылаются на один и тот же локальный WOFF2: ранее это были четыре побитово одинаковые копии.


## Исправления QA от 4 ноября 2026

Сохранение и удаление подарка сериализованы до подтверждения Firestore; смена формы и выход заблокированы. Бронирование и снятие выполняются транзакцией с проверкой прежнего статуса, конфликт не сообщает об успехе. Это разрешение конкуренции транзакцией, без добавления серверных полей блокировки. Автоматического seed в рабочем клиенте нет; схема и правила доступа не менялись. Панель фильтров находится в обычном потоке на всех ширинах. Закрытые описания inert и aria-hidden; заголовок содержит отдельную кнопку раскрытия. Escape и уход фокуса закрывают меню. Ошибки редактора выводятся внутри диалога, общие уведомления закреплены внизу окна. Загрузчик bootstrap.js обрабатывает отказ импорта и ожидание более 15 секунд с кнопкой повтора.

Проверки: `node scripts/test-write-safety.mjs` — конкурентная бронь, откат ошибки, блокировка второго сохранения и отсутствие автоматического seed; UI-регрессия 1440×900 и 390×844 — раскрытие, inert, Escape, прокрутка, ошибки диалога. Проверить недоступность CDN и повтор загрузки отдельно от отказа записи.


## Резервирование и черновики — 4 ноября 2026

Два раза в месяц GitHub Actions читает Firestore, валидирует и коммитит снимок; runtime этот файл не читает. Черновики подарка сравниваются с исходными значениями формы, черновик подсказок — со значениями при открытии диалога. beforeunload предупреждает при отличиях или незавершённой записи; отмена, смена редактируемого подарка и выход запрашивают подтверждение отбрасывания. Возврат полей к исходным значениям и успешное сохранение снимают предупреждение.


## Владение бронью — 5 ноября 2026

Гостевой клиент использует отдельный именованный Firebase App `wishlist-guests-v1` в guest-client.js, собственные Auth и Firestore; админка остаётся на default App. Просмотр публичный. При первой записи ensureGuest восстанавливает сессию или вызывает signInAnonymously, требует постоянное хранилище browserLocalPersistence либо indexedDBLocalPersistence. Это только сессия SDK, подарки/брони в браузерное хранилище не записываются. Одновременная авторизация сериализуется promise и Web Locks при поддержке браузером. reservation-policy.js задаёт допустимые клиентские переходы; сервер повторяет ограничения в firestore.rules. Владелец после повторного входа в тот же профиль может снять бронь. Админский вход/выход не меняет гостевой UID. Старые статусы и тексты не перезаписываются.

## Новые клиентские состояния — 5 ноября 2026

app.js хранит независимо mode, category, filter, sort. «Отложенные» фильтруют загруженные подарки по локальным ID и сортируют по желанию; дополнительные запросы не выполняются. bookmarks.js читает/пишет только массив ID под ключом wishlist-bookmarks-v1; storage event синхронизирует вкладки. Ошибка записи оставляет подборку до закрытия страницы с понятным уведомлением. Prune разрешён только на серверном snapshot без pending writes. Вложенный featured-контейнер не меняет обработчики карточек; поиск фокуса выполняется по всем вложенным gift-card.

Поле reason обрабатывается обоими клиентами и rules. Кнопка ожидания работает до завершения транзакции, затем открывается отдельный native dialog. В админке surprise — только переменная текущей страницы, без сохранения настройки и без изменения серверных данных.
