# Безопасность

## Фото в публичной версии

- В репозиторий и на сайт попадает только оптимизированная копия `dist/assets/hero.jpg`, повторно сохранённая без EXIF и другой исходной метаинформации.
- Исходное фото, рабочие варианты и скриншоты исключены из Git и остаются только локально.
- Поскольку страница публичная, посетитель технически может сохранить показанную hero-копию. Запретить это средствами HTML/CSS невозможно; защита строится на том, что оригинал и его метаданные не публикуются.
- Публичная и административная страницы используют `noindex`, `noarchive` и `noimageindex`; `robots.txt` также запрещает обход сайта. Добросовестные поисковые роботы не должны индексировать страницу и hero-изображение.

## Граница доверия

Клиентский JavaScript считается недоверенным. Все реальные права и ограничения задаются в `firestore.rules`. Публичная Firebase web-конфигурация не является паролем и может находиться в статическом файле; учётные данные администратора и service-account ключи в репозиторий не добавляются.

## Права

- Читать `gifts`: любой посетитель.
- Менять только `status` существующего подарка: любой посетитель.
- Создавать, полностью редактировать и удалять: только пользователь с техническим email `admin@birthday-wishlist.local`.
- Все остальные коллекции и документы: запрет по умолчанию.

Даже если злоумышленник вызовет Firebase API напрямую и зарегистрирует другой аккаунт, правила не дадут ему административных прав. При расширении команды технический email нужно заменить UID allowlist или custom claims.

Админка запрашивает только пароль. Для Firebase Auth используется неперсональный технический адрес `admin@birthday-wishlist.local`, зафиксированный в клиентском коде; он не является секретом и не раскрывает личную почту владельца.

## Серверная валидация

Правила проверяют белый список полей, типы, длины, диапазоны, допустимый статус и тип `createdAt`. Для публичного обновления используется `diff().affectedKeys().hasOnly(['status'])`.

## Осознанное ограничение

Гости не авторизуются, поэтому система не знает, кто поставил бронь. По требованию продукта любой гость может снять любую бронь после явного предупреждения. Если понадобится правило «снять может только забронировавший», потребуется анонимная авторизация и отдельный токен владельца брони.

## Контроль перед публикацией

- В Firebase Auth включён только Email/Password.
- Саморегистрация отсутствует в интерфейсе.
- В `dist/assets/firebase-config.js` нет паролей, приватных ключей и service-account JSON.
- `firestore.rules` опубликованы и проверены Rules Playground/Emulator.
- Для Auth включены password policy и email enumeration protection, если доступны в консоли.
- `/admin/` содержит `noindex` и не связан с главной страницей.
