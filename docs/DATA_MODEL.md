# Модель данных

## `siteContent/giftGuidance`

| Поле | Тип | Ограничение |
|---|---|---|
| `things` | string | обязательная непустая строка до 4000 символов |
| `brands` | string | обязательная непустая строка до 4000 символов |
| `updatedAt` | timestamp | серверное время последнего сохранения |

Документ публично читается, создаётся и обновляется только администратором, удаление запрещено. Это отдельная сущность и не влияет на схему подарков.

## Версионируемый снимок

`data/firestore-snapshot.json` хранит точный список документов `gifts` (включая ID, характеристики, статус, `createdAt` и время обновления Firestore) и текущий `giftGuidance`. Поле `capturedAt` показывает время выгрузки. Файл предназначен для восстановления и аудита через историю Git, но не является runtime-источником данных.

## Коллекция `gifts`

| Поле | Тип | Ограничение |
|---|---|---|
| `id` | ID документа | Уникальный, в документе не дублируется |
| `title` | string | Обязательное, 1–120 символов |
| `description` | string | 0–4000 символов |
| `desireLevel` | integer | От 1 до 5 |
| `price` | integer или null | 0–9 999 999 ₽ или отсутствует |
| `category` | string или null | Необязательный стабильный код: `Self Care & Cosmetics`, `Sport`, `Just Pleasure`, `Food`, `Needs`; в интерфейсе отображается русской подписью |
| `status` | string | `available` или `reserved` |
| `createdAt` | timestamp | Время создания для стабильной сортировки |

Неизвестные поля запрещены правилами Firestore.

Цена `0` — заданная цена, отображается как «≈ 0 ₽» и участвует в сортировке. Пустое поле сохраняет `null`. Поле админки принимает максимум семь ASCII-цифр 0–9; пробелы по краям вставленного значения обрезаются. Знаки, дроби, экспоненты и буквы не принимаются. Оба клиента используют `gift-price.js`, сервер проверяет целый тип и тот же диапазон; существующие подарки при обновлении интерфейса не перезаписываются.

Коды категорий намеренно не переименовываются в существующих документах: `Self Care & Cosmetics` отображается как «Забота о себе», `Sport` — «Жопу качат», `Just Pleasure` — «Дофаминовый всплеск», `Food` — «Еда», `Needs` — «Практичное». Это сохраняет все ранее назначенные значения без миграции Firestore.

Для обратной совместимости документ без поля `category` читается как подарок без категории. Новые и отредактированные документы сохраняют `category: null`, если в форме выбрано «Без категории». Список значений фиксирован в `dist/assets/categories.js`; отдельной сущности категории в Firestore нет.

## Стартовые данные

Канонический список хранится в `dist/assets/seed-data.js`. В нём 57 позиций из запроса пользователя. При первичной записи каждому подарку назначаются:

- `desireLevel: 1`;
- `price: null`;
- `category: null`;
- `status: "available"`;
- последовательный `createdAt` для стабильного порядка.

Автоматическое заполнение отключено в рабочей админке. `seed-data.js` сохранён как исторический стартовый набор, но не импортируется административным клиентом. Пустой серверный список не запускает запись.

## Изменение схемы

При добавлении или удалении поля нужно синхронно изменить:

1. `firestore.rules`;
2. публичное чтение/рендер в `app.js`;
3. форму и CRUD в `admin.js`;
4. стартовые данные при необходимости;
5. эту документацию и проверки.


## Исправления QA от 4 ноября 2026

Сохранение и удаление подарка сериализованы до подтверждения Firestore; смена формы и выход заблокированы. Бронирование и снятие выполняются транзакцией с проверкой прежнего статуса, конфликт не сообщает об успехе. Это разрешение конкуренции транзакцией, без добавления серверных полей блокировки. Автоматического seed в рабочем клиенте нет; схема и правила доступа не менялись. Панель фильтров находится в обычном потоке на всех ширинах. Закрытые описания inert и aria-hidden; заголовок содержит отдельную кнопку раскрытия. Escape и уход фокуса закрывают меню. Ошибки редактора выводятся внутри диалога, общие уведомления закреплены внизу окна. Загрузчик bootstrap.js обрабатывает отказ импорта и ожидание более 15 секунд с кнопкой повтора.

Проверки: `node scripts/test-write-safety.mjs` — конкурентная бронь, откат ошибки, блокировка второго сохранения и отсутствие автоматического seed; UI-регрессия 1440×900 и 390×844 — раскрытие, inert, Escape, прокрутка, ошибки диалога. Проверить недоступность CDN и повтор загрузки отдельно от отказа записи.


## Владение бронью — 5 ноября 2026

Добавлено необязательное `reservedBy: string | null` (UID Firebase Auth, 1–128 символов). Новая бронь хранит UID гостя, свободный подарок — null. Старое отсутствующее поле читается как null; старая reserved-бронь без владельца снимается только администратором. При снятии status и reservedBy меняются атомарно. Новые подарки создаются available/null. Редактирование характеристик не меняет владельца. Миграция существующих документов не требуется и не выполнялась. Снимок сохраняет UID, но не токены Auth; CSV по-прежнему содержит пять прежних столбцов.
