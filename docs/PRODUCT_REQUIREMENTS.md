# Требования к продукту

## Назначение

Сайт помогает гостям выбрать подарок и пометить его как забронированный, чтобы сюрпризы не повторялись. Владелец управляет списком через скрытую админ-панель.

## Роли

### Посетитель

- не регистрируется и не входит;
- видит общий список подарков;
- фильтрует список по статусу и сортирует его;
- раскрывает карточку, если есть описание;
- бронирует подарок и снимает бронь после подтверждения;
- не может создавать, редактировать или удалять подарки.

### Администратор

- единственный пользователь Firebase Authentication;
- входит на `/admin/` только по паролю; технический email Firebase скрыт внутри приложения и не требует ввода;
- создаёт, редактирует и удаляет подарки;
- видит, но не меняет статус бронирования в форме;
- при первом успешном входе автоматически заполняет пустую базу стартовым списком.

## Публичная страница

- Hero: крупная типографика слева, портрет именинника справа без видимой прямоугольной границы.
- 57 стартовых подарков, у каждого желание `1/5`, цена отсутствует, статус `available`.
- Фильтры: «Все», «Доступно», «Забронировано».
- Сортировки: желание по убыванию/возрастанию, цена по убыванию/возрастанию.
- При сортировке по цене подарки без цены всегда идут после подарков с ценой.
- Счётчик использует правильную русскую форму слова «подарок».
- URL в описаниях становятся безопасными кликабельными ссылками.
- Состояния: три skeleton-карточки, пустой список, ошибка с повтором, сообщение об ошибке записи.

## Админ-панель

- Нет ссылки на админку на публичной странице.
- Страница содержит `noindex, nofollow, noarchive`.
- Поля подарка: название, желание 1–5, необязательная цена, необязательное описание.
- Новый подарок всегда `available`.
- Удаление подтверждается inline, без системного `confirm()`.

## Не входит в продукт

- аккаунты гостей и принадлежность брони конкретному человеку;
- фотографии конкретных товаров;
- платежи, корзина, доставка;
- хранение данных в браузере;
- OpenAI API или любые GPT-функции.
